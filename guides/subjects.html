照护对象技术说明

人员和宠物共用管理流程，按类型调用接口；保存后回读详情和列表再更新界面。

资料写入仅开放给本人名下 ACTIVE 的 PERSON / PET。本人账号资料是另一类资源。 不提供人员或宠物档案分享；头像和设备绑定仍各自按原规则处理。

1用哪些接口

  1. 读取照护对象列表GET/app/subjects进入管理页及保存后刷新
  2. 创建人员 / 宠物POST/app/subjects/personPOST/app/subjects/pet只发送一次 POST
  3. 读取对象详情GET/app/subjects/person/{personId}GET/app/subjects/pet/{petId}进入详情、写入前后核对
  4. 修改资料、头像或归档PATCH/app/subjects/person/{personId}PATCH/app/subjects/pet/{petId}按操作发送差量 PATCH
  5. 读取关联设备GET/app/subjects/person/{personId}/device-bindingsGET/app/subjects/pet/{petId}/device-bindings详情展示及归档前检查
  6. 检查分享关系GET/app/subjects/person/{personId}/sharesGET/app/subjects/pet/{petId}/shares当前用于归档前检查
  7. 上传对象头像POST/sys-file/upload用户确认预览后上传

路径中的 personId / petId 是对象数字 ID。页面中的 PERSON:101 / PET:101 是带类型的标识，不能整个放进数值路径。

2业务流程怎么走

  1. 读取

    按人员 / 宠物筛选列表；点击对象后读取详情和关联设备，不用名称识别对象。

  2. 新增

    校验表单，POST 一次；使用返回的对象 ID 查询详情，再查列表确认出现。

  3. 编辑

    保存前重读详情，检查待改字段没有被其他入口修改；PATCH 差量后回读详情和列表。

  4. 删除

    页面按钮称“删除”，实际 PATCH status=ARCHIVED。重新确认归属、状态及设备 / 历史分享关系后提交，再回查详情和列表。

删除后资料保留但退出当前列表，暂不支持恢复；不自动解绑、撤销服务器历史授权或回收头像。任何历史分享记录非空仍会阻止当前删除流程。

3字段怎么提交

字段 / 区域来源 / 内容处理规则
创建公共部分type、displayName、profile未填写项省略；名称必填，PERSON / PET 必须与入口一致。
身高与体重创建：profile.heightCm / weightKg；编辑：height / weight创建和 PATCH 不能直接复用同一个请求对象；宠物没有身高项。
人员资料gender、birthDate、relationToOwner、healthMonitoringEnabled创建放 profile；编辑放根层。生日为 YYYY-MM-DD，false 不能当作未填写。
宠物资料species、breed、gender、birthDate、neutered、activityTargetMinutes新增 species 必须选 DOG / CAT / OTHER；neutered 发送 1 / 0，数值 0 要保留。
对象头像PATCH 顶层 avatarUrl先上传再保存返回地址，移除发送空串；与本人账号的 avatar 字段不同。

普通资料目前不支持清空已有值，不能把 null、空串和省略当成同一种操作。头像移除是单独实现的例外。

4失败时怎么处理

  • 写入结果未确认

    请求超时或回查不一致时先刷新核对，不自动重发 POST / PATCH，也不能按名称猜测创建成功。

  • 编辑冲突

    待改字段与编辑基线不一致时停止保存，刷新后重新编辑。

  • 关联未确认

    设备或分享关系读取失败时阻止归档，不能把读取失败当作空列表。

  • 头像失败

    上传和保存地址分别确认；上传成功但资料保存失败，不等于头像已更新，也不自动删除服务器文件。

5哪些内容还要补

  • 尚未开放

    普通资料清空、备注、创建时选图上传、归档对象列表及恢复。

  • 后端待确认

    PET species 文档差异、历史分享关系下的删除约束、上传文件可信回收。人员 / 宠物档案分享不再是待实现项。

对象头像沿用账号头像的图片校验与上传接口；新增 / 编辑 / 归档的既有验收范围见主仓库对应验证记录，本轮只整理说明。

公共约定：需登录的业务请求使用 Bearer Token，后台公共层携带 lang 与地区格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。OAuth、账号、AI 客服和图片客户端按各自规则处理。
