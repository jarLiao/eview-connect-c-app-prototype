AI 客服技术说明

先创建问题取得 messageId，再用 SSE 逐段接收回答；停止、失败和完成分别处理。

通用客服会话与设备概览 / 健康、单条告警分析使用不同接口；后两类分别见设备详情和 AI 告警分析专题，不把聊天接口当作设备分析接口。

1用哪些接口

  1. 读取当前默认模型GET/aiModel/list进入聊天预取；发送时按缓存情况再读取
  2. 创建用户问题POST/chat/createPOST 返回 messageId 字符串，不是完整回答
  3. 读取该问题的回答流GET/chat/msg/listquery：key=messageId；Accept: text/event-stream

请求使用当前环境、Bearer Token、TENANT-ID、lang 和 X-TimeZone。一次 stream 开始时固定语言，模型查询、POST 和 SSE 共用该快照；后续消息再读当前语言，切语言不改写正在返回的流。

模型列表按环境 / 租户 / 用户缓存 10 分钟。根据模式选择 Chat 或 Reason 类型，优先服务端 defaultModel，再选该类型首个模型。读取失败可用旧缓存 / 内置兜底；成功列表缺所需类型则明确提示不可用。

2一条消息怎么完成

  1. 准备会话

    每种模式维护独立 conversationId、输入和消息；同一模式已有请求时禁止再次发送，创建用户消息和等待中的回答占位。

  2. 创建问题

    选择模型并提交 /chat/create；先判 HTTP 和业务响应，再把 data 解析为 Long messageId，用其字符串值作为流读取 key。

  3. 读取回答

    打开 SSE，将回答、推理、工具和来源映射为不同事件；只更新该模式、该回答占位，不重复创建气泡。

  4. 收尾

    完成转为已结束；网络失败保留已收内容并标失败。用户停止或离开页面取消流，保留内容并标 STOPPED。

切换模式只切换展示，旧模式请求可以继续；退出聊天或更换设备 / 告警入口时停止全部模式请求。

3字段和事件怎么用

字段 / 区域来源 / 内容处理规则
会话与消息conversationId；POST 返回 data → messageId → GET keyconversationId 当前按模式生成 UUID 会话串；messageId 不是本地气泡 ID。数值 ID 保持无损，不经浮点数转换。
问题内容role=user、content、time、modelNamecontent 去首尾空白；time 按手机时区生成 yyyy-MM-dd HH:mm:ss；modelName 来自模型选择结果。
模式与上下文datasetId、tenantId、extDetails、websearch、inner四模式 datasetId 为 0 / -3 / -7 / -8；extDetails 带用户 / 租户，MCP 另需 mcpId；当前 websearch=false、inner=false。
SSE 正文纯文本 / delta；content、answerText 等累计文本纯文本和 delta 追加；累计快照提取新增部分，重复内容不重复展示；推理 reasoningContent 单独显示。
工具与来源toolInfo / toolInfoList；extLinks工具按内容去重，来源按 URL 或标题去重；正文、推理、工具、来源不混为一种文本。
完成信号done / complete、[DONE]、finish / finished去掉结尾完成标记；当前正常关闭且已收到有效片段也作完成，空流失败。HTTP 200 建立连接不代表已收到回答。
请求语言公共 lang 与消息 languageTag 快照发送时固定语言供 POST / SSE 使用，切语言不把已有流改成另一语言；界面语言和用户提问语言的策略分开判断。

当前请求体不发送 temperature、top_p、max_tokens 或 systemPrompt；不能把其他 AI SDK 的默认参数当成本接口字段。

4取消和重试怎么处理

  • 发送 / 流失败

    空 messageId、非法 ID、业务失败及 SSE 错误均标失败；已有正文保留，并解除当前模式发送限制。

  • 手动重试

    失败气泡可重试：在同一会话重新 POST 原问题，取得新 messageId；保留原用户气泡，替换失败的回答占位，不是从旧流断点继续。

  • 主动停止

    先发布 STOPPED 状态，再取消 SSE；无内容显示已停止，有内容保留已收部分。停止本地连接不证明服务器已停止生成。

  • 返回恢复

    同一账号 / 环境 / 入口可恢复进程内快照和输入；旧 STREAMING 改为 STOPPED，不自动恢复流。进程被杀后没有服务端历史恢复能力。

5哪些内容还要补

  • 设备上下文

    当前设备 / 告警入口用于本地会话隔离，未发送类型化设备、对象或告警字段；不能据此声称 AI 已读取该设备实时数据。

  • 服务端契约

    消息历史、断点续传、停止生成、错误事件和正常关闭的统一规则，以及人工客服 / 工单入口仍需确认。

  • 验证边界

    本轮只对照代码，不新增 AI 请求。四模式模型 / MCP 可用性、发送期间切账号或环境、真实弱网与长流需独立验收。

  • 已有语言验证

    10-21 自由模式英文问答通过；中文界面下 MCP 英文提问仍返回中文，知识库缺可访问内容，均保持待确认。

公共约定：需登录的业务请求使用 Bearer Token，后台公共层携带 lang 与地区格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。OAuth、账号、AI 客服和图片客户端按各自规则处理。
