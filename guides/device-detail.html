设备详情技术说明

设备基础状态与健康告警分开读取；基础信息先显示，规则结果返回后再补 AI 内容。

先确认设备仍属于当前账号可访问的自有对象。健康 / 告警已接入，是否有数据取决于所选环境。

1用哪些接口

  1. 在线状态、定位和遥测GET/app/device/{deviceId}/stateGET/app/device/{deviceId}/realtime复用设备列表发现及读取链路
  2. 设备产品资料GET/app/device/{deviceId}/product确认关系后读取，可单独降级
  3. 设备直接分享记录GET/app/device/{deviceId}/shares只读，不代表邀请操作开放
  4. 概览指标与摘要GET/app/evaigc/devices/{deviceId}/overview先 includeSummary=false，再 true
  5. 日 / 周 / 月健康数据GET/app/evaigc/devices/{deviceId}/health首次进入或切换周期时读取
  6. 近期告警列表GET/app/evaigc/devices/{deviceId}/alerts进入设备后读取
  7. 单条告警解释GET/app/evaigc/devices/{deviceId}/alerts/{alertId}/analysis打开告警后先 includeAi=false，再 true

新增分析接口来自当前客户端声明，不在原 37 项 App Device / App Subject 快照中。原有 /events 与这组告警读取接口不是同一入口。

2页面怎么加载

  1. 确认设备

    以 deviceId 查当前对象关联；不能因为 state / realtime 能访问就认定拥有该设备。

  2. 填充基础区域

    展示状态、遥测、使用者和产品；各区域独立保留加载、空数据和失败状态。

  3. 读取分析

    读取概览和告警列表。概览先展示规则结果，再请求 AI；健康首次进入标签才读取。

  4. 按交互补充

    切换健康周期重新读取；点告警后请求该 alertId 的规则解释及 AI，关闭时取消解释请求。

3每个区域展示什么

字段 / 区域来源 / 内容处理规则
在线 / 电量 / 位置state、realtime沿用设备列表规则；状态未知不能显示离线，电量 0% 不能丢弃。
产品与使用者product + 对象绑定产品信息和关联对象分别读取；设备昵称不因 productName 存在而自动获得。
概览与健康指标metrics 的 value / unit / available使用服务端单位与可用标记；没有值显示 —，不补零。
健康趋势trend.points、period、date日 / 周 / 月分别读取；date 当前按 UTC 日期，小时桶转换为手机时区展示。
告警alerts 的 alertId、timeMillis、risk按实际返回展示；告警解释使用同一设备与 alertId，不等于推送或已读状态。
AI 摘要 / 解释summary / analysis、riskAI 返回后替换同一请求区域；失败保留已有规则结果，不编造分析。

4刷新和失败怎么处理

  • 基础数据

    前台每轮结束约 15 秒后刷新 state / realtime；离页或后台停止。更新不重建地图或强制复位视野。

  • 分析数据

    不跟随 15 秒轮询反复请求 AI。手动刷新重读概览、告警及已打开过的健康区域。

  • 环境未部署

    404 显示环境未提供；拒绝或返回无效时清除受限结果，不把缺数据解释成健康正常。

  • 读取慢或失败

    规则先显示，AI 独立等待；AI 失败不自动重试。普通网络失败可保留同设备上次结果并标记失败。

  • 切换设备 / 账号

    取消旧请求，并核对设备、账号和环境后才接收响应，避免旧结果覆盖新页面。

5哪些内容还要补

  • 环境差异

    既有记录中范工环境可读取分析接口，29999 未部署时返回 404；本轮未重新测试服务器。

  • 服务端问题

    健康分析时段、风险窗口口径及定位距离异常待处理；不能把当前 AI 输出视为已校准结论。

  • 尚未形成完整流程

    真实设备持续移动、分享操作、告警处置与推送、轨迹围栏和云配置。定位读取与指令见地图说明。

公共约定：业务请求带 Bearer Token 与 IANA 格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。认证、图片等专用客户端按各自规则处理。
