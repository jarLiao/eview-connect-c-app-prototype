登录与账号安全技术说明

登录先建立 OAuth 会话；注册和找回密码在最终提交时校验验证码，完成后返回登录页。

覆盖密码登录、会话恢复、注册、找回 / 修改密码及退出。本人资料编辑另见账号资料说明。

1用哪些接口

  1. 登录或刷新 TokenPOST/oauth2/token同一路径，切换 grant_type；响应直接是 Token 对象
  2. 显式校验当前会话GET/token/check_token按需调用；启动恢复不逐次请求此接口
  3. 登录后补齐本人资料GET/user/info资料暂时不可读不否定已建立的会话
  4. 发送注册 / 找回验证码GET/sysMessage/send/app/emailCoderegistered=false 注册，true 找回；GET 会发送邮件
  5. 注册、找回和修改密码POST/register/userPOST/register/forget/{code}POST/register/password分别使用对应请求体，不共用登录表单
  6. 退出当前登录DELETE/token/logout请求远程退出，同时清理本地会话与当前对象选择

OAuth 登录 / 刷新使用配置生成的 Basic Authorization，以及 Enc-Flag=false、skipTenant=true、skipToken=true。业务 Bearer 头不能直接套用到取 Token 请求。

登录密码按当前 PasswordEncryptor 的 AES/CFB/NoPadding → Base64 处理；密钥 / IV 不写入文档。注册、找回、改密当前直接按各自 JSON DTO 传参，不能自行套用登录加密。

发码使用 App-Client-Id，注册 / 密码接口使用 X-Client-Id；所有客户端统一带 IANA 格式的 X-TimeZone。

2业务流程怎么走

  1. 密码登录

    校验输入，POST grant_type=password；校验 Token 响应，保存会话后读取 /user/info，再进入首页。

  2. 启动恢复

    等待本地会话读取完成。有 Token 且到期时间超过当前 60 秒时直接恢复；否则使用 refresh_token 续期。

  3. 注册 / 找回

    邮箱发码 → 输入 4 位码 → 填账号 / 新密码 → 最终 POST。验证码页只校验格式，没有独立验证码校验请求。

  4. 修改密码

    使用当前会话的 username、原密码和新密码；成功后走退出流程，清理登录导航并要求重新登录。

  5. 退出

    二次确认后请求 /token/logout；普通远程失败仍清理当前本地会话，旧退出回包不能清掉后来建立的新会话。

注册 / 找回完成后返回登录页并预填账号，不自动当作已经登录。刷新 Token 缺新 refresh_token 时保留原值。

3参数怎么提交

字段 / 区域来源 / 内容处理规则
OAuth 登录query：username、grant_type=password、scope；表单：passwordapplication/x-www-form-urlencoded；username 是登录账号，不用昵称替代。
OAuth 刷新query：grant_type=refresh_token、scope；表单：refresh_token刷新串放表单；access_token / expires_in 必须有效，expires_in 单位为秒，再换算 expiresAtMs。
注册username、password、email、tenantId、code、registerType、loginType当前 registerType=EMAIL、loginType=PWD；租户来自调用配置，不由输入表单任意指定。
找回 / 改密找回：email、code、newpassword1 等；改密：username、password、newpassword1找回路径 code 与 JSON code 一致；改密 username 取会话原值，不把邮箱当成已确认 username。
表单校验username、password、confirmPassword、acceptedAgreement注册用户名 4–20 位字母数字下划线；新密码至少 8 位且含大小写与数字；确认密码、协议勾选只用于本地校验。
发码节流4 位验证码，60 秒重发倒计时倒计时从发码成功开始；真实有效期、错误次数和频率限制仍由服务端确定。

公共命令接口按业务包装判定成功，data=null 不单独视为失败；OAuth Token 响应不能套用 ApiResponse 的解析器。

4失败时怎么处理

  • 恢复失败

    刷新明确拒绝或没有 refresh_token 时清当前会话并回登录；临时网络 / 服务端失败保留会话，界面仍可进入，业务区域提示失败与重试。

  • 读取遇到过期

    普通网络层只对 GET / HEAD 的 HTTP 401 或约定的 token expired 424 刷新；同一会话的并发刷新合并，成功后重发该读取一次。

  • 写入遇到过期 / 超时

    POST / PUT / PATCH / DELETE 不套用自动刷新重放；结果不明时先核对，避免重复注册、修改或发送业务指令。

  • 验证码错误

    最终提交提示验证码错误 / 过期时返回验证码步骤，保留账号表单；其他错误留在当前步骤，发送和提交期间禁用重复点击。

  • 切账号 / 环境

    刷新保存与退出清理核对会话版本，过时回包不覆盖新登录。Token、密码、验证码及客户端密钥不进入导出或日志。

5哪些内容还要补

  • 后端待确认

    公共账号接口的 App 使用范围、OAuth / 加密参数、验证码有效期及限流错误码、多终端会话撤销规则。

  • 尚未接入

    第三方登录 / 绑定、账号注销、登录设备管理；原型对应按钮不能作为正式能力依据。

  • 验证边界

    注册 / 找回已有用户实测记录；本轮只对照代码整理，未发邮件或修改密码。过期、弱网、切账号等分支仍需按当前制品真机验收。

  • 既有证据

    09-28 注册、邮箱发码和找回密码为用户实测确认；租户 / 角色映射与全部会话异常仍需独立验证。本轮未发送邮件或修改账号。

公共约定：业务请求带 Bearer Token 与 IANA 格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。认证、图片等专用客户端按各自规则处理。
