云端查找设备技术说明

自有设备详情点击“查找”，App 只发送一次 findMe；服务器受理、硬件 ACK 和现场声音分开确认。

查找用于让设备响铃或提示，不获取新 GPS。原型按钮仅显示演示提示，本专题从设备详情说明及说明目录独立打开。

1用哪些接口

  1. 向自有设备发送查找命令POST/app/device/{deviceId}/functionPOST /function?functionId=findMe，JSON body：{}

App 先确认当前账号自有关系与设备 ID；页面和 Repository 同时禁止并发重复发送。请求使用当前环境和会话快照。

立即定位使用同一路径的 singleLocating，但属于另一个业务；本次查找不替代定位更新。

2业务流程怎么走

  1. 点击与预检

    所有者在详情点击查找，检查当前设备关系、页面忙碌状态和账号 / 环境，发送中禁用重复操作。

  2. 下发请求

    以 functionId=findMe 和 {} 发送一次 POST；设备、会话或环境变化后拒绝旧响应。

  3. 页面反馈

    HTTP 与业务返回有效、data 为非空文本时提示请求已发送，请留意设备提示音；不直接显示响铃成功。

  4. 效果核对

    联调时另查设备真实 ACK，并由现场人员确认声音。重新进入、刷新或冷启动不自动重发命令。

3字段和结果怎么看

字段 / 区域来源 / 内容处理规则
资源deviceId仅当前账号确认的自有设备，不从共享只读页面触发。
指令functionId=findMe；body={}不附带坐标，不复用参数配置 payload，也不更改设备配置。
回执code=0、ok≠false、data 非空字符串仅确认正式接口已受理；设备 ACK 和真实声音需另行核对。
位置realtime 的 latestLocation查找本身不产生新位置结论；GPS 更新属于地图与立即定位专题。

4离线和超时怎么处理

  • 离线

    根据中英文业务消息识别 Device is offline / 设备离线，提示设备离线，不误报普通网络失败。

  • 拒绝与失权

    无自有关系、鉴权拒绝或业务拒绝不报告发送成功；当前会话变化则丢弃旧反馈。

  • 结果不明

    超时、断网、响应不完整或缺必要字段保持未确认；不自动重试，先确认设备是否已响铃再手动决定。

  • 重进与冷启动

    显示读取状态，不回放历史查找命令；发送互斥不把重复点击排队到稍后补发。

5已验证与待补内容

  • 已有实机证据

    10-20 云端 HID 中继收到真实查找 ACK，用户确认听到声音；10-21 新 App 首轮查找也获成功 ACK 与用户听音确认。

  • 最终包边界

    10-21 最终修复包第二次查找 ACK 和页面通过，用户回复“刚才未留意”，该次声音未确认；离线、重进和冷启动未重发有记录。

  • 仍待验收

    最终包现场声音补验、真实蜂窝直连、其他型号 / 固件与全部网络异常。中继只证明服务器—电脑—真实设备链路。

公共约定：业务请求带 Bearer Token 与 IANA 格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。认证、图片等专用客户端按各自规则处理。
