AI 告警分析技术说明

打开一条设备告警，先显示规则解释，再补 AI 分析；失败、取消和失权各自处理。

说明正式 Android 的只读告警分析链路。原型弹层只展示合成结果，不调用服务器；不代表推送、已读、处置或真实告警验收。

1用哪些接口

  1. 取得可打开的设备告警GET/app/evaigc/devices/{deviceId}/alertsGET 列表返回 alertId；按 timeMillis 倒序展示，保留 truncated 标记
  2. 读取规则与 AI 解释GET/app/evaigc/devices/{deviceId}/alerts/{alertId}/analysis同一路径请求两次：includeAi=false 成功后，才请求 includeAi=true
  • 请求上下文

    沿用公共 Authorization: Bearer、lang 和 X-TimeZone；deviceId 与 alertId 放在路径，includeAi 放在 query，无请求体。

  • 与其他分析分开

    单条告警使用 includeAi；概览 / 健康使用 includeSummary。此链路不走 AI 客服的 chat/create 或 SSE，也不由客户端额外注入客服专用 TENANT-ID。

  • 权限

    自有关系或有效 ALERT 分享授权才可读取。综合概览另需 HEALTH + ALERT，不能用概览是否可读代替单条告警的权限判断。

2规则与 AI 怎么加载

  1. 选中告警

    点击设备告警，记录当前 deviceId、alertId 和生效语言，清除上一条解释。原告警的类型、时间和描述可以先展示。

  2. 先读规则

    GET analysis?includeAi=false。成功后显示规则解释和建议；失败则结束本轮，不继续请求 AI。

  3. 后台补 AI

    再 GET analysis?includeAi=true，保留规则内容并显示 AI 等待状态；成功后整体替换同一告警的分析结果。

  4. 结束或取消

    AI 失败保留本轮规则结果；关闭弹层取消分析，切告警取消旧请求。15 秒基础状态轮询不触发 AI；重新打开告警才开始新一轮。

3结果字段怎么展示

字段 / 区域来源 / 内容处理规则
告警标识alertId / alert.alertId使用列表中的合法 ID；响应顶层 alertId 若存在，必须与请求一致，不用其他告警结果填充。
告警基本信息alert.alarmType / alarmTypeText / timeMillis / description有分析返回的告警则显示它，否则沿用选中项；时间为毫秒并按手机时区显示，缺失时间显示未知。
风险risk.level / levelText / reasons显示服务端结果；缺失不当作低风险，不由客户端生成风险分数。
解释与建议title / advice / analysis.text / analysis.source保留规则或 AI 来源；没有解释不填演示文案，AI 内容只用于辅助理解。
列表边界alerts / truncated / notes列表为空不等于已完成告警处置；truncated 表示返回被截断，不能推定已读到全部历史。

X-TimeZone 不能证明所有统计窗口均按本地时间；时区、风险回溯窗口及统计口径仍按公共约定与后端问题分别核对。

4失败、取消和失权怎么处理

  • 规则失败

    没有规则结果时显示对应失败或不可用状态，不继续发起 AI 请求，不伪造分析成功。

  • AI 失败

    保留已经取得的规则内容并标记 AI 失败，不自动重试。专用读取超时为 60 秒、整次调用上限 75 秒，不等于服务端已取消生成。

  • 接口与拒绝

    404 按环境未提供处理；400 为请求无效；403 或非零业务 code 按拒绝处理。不直接展示可能包含其他设备信息的服务端原文。

  • 切告警与关闭

    每轮请求有独立序号；关闭取消，切告警替换当前任务。旧请求即使迟到，也不能写入新告警区域。

  • 语言与身份

    切语言清除旧文案后重读，同设备可保留选中告警。Repository 在调用前后核对账号 / 环境和 ALERT 授权；权限刷新或设备变化时清理不再可读的结果。

5已接入与待验证范围

  • 当前实现

    正式客户端已有告警列表、规则先显 / AI 后补、弹层关闭取消、语言重读及身份 / 权限校验；接口源为客户端声明，不改写 10-10 OpenAPI 历史快照。

  • 既有证据

    10-12 有分析接口接入记录，10-21 固定机中英文概览 / 健康读取保留；当时缺健康样本、无告警，不能因此宣称本次已验证真实告警分析准确性。

  • 共享环境差异

    10-28 的 81 共享健康 / 告警 / 概览仍被要求绑定；用户反馈范工请求可通、81 待同步。共享单条告警解释仍需同步后的环境和样本复验。

  • 推送与处置

    读取列表和 AI 解释不会设置已读、重要或已处理，也不表示 FCM / HMS 已接通。消息到达、去重、已读与告警处置仍另行确认。

  • 本轮范围

    仅补齐说明、页面关联和离线下载；未请求真实 AI、制造告警或写入设备。项目仍处内部试用准备，尚未正式提测。

公共约定：需登录的业务请求使用 Bearer Token，后台公共层携带 lang 与地区格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。OAuth、账号、AI 客服和图片客户端按各自规则处理。
