消息、邀请与通知技术说明

Prod消息页当前处理设备分享邀请；设备告警查询、系统通知权限和后台推送是不同链路。

仅直接DEVICE邀请。原型中告警、系统消息和未读数字仍为合成演示，不代表正式App已经接入。

1当前使用哪些接口

  1. 读取收到/发出的邀请GET/app/subjects/shares/receivedGET/app/subjects/shares/granted按当前账号、方向、状态与DEVICE资源过滤
  2. 处理收到的待确认邀请POST/app/subjects/shares/{shareId}/acceptPOST/app/subjects/shares/{shareId}/reject每次命令提交一次，再独立回查记录

Prod的alertHistoryEnabled=false、shareInboxEnabled=true。消息页不以设备evaigc告警列表代替全局消息，不调用已停用的/c/v1未读计数，也不因/events可读就开放已读/处置。

2邀请怎么处理

  1. 读取列表

    默认收到/待确认，可切收发方向和状态；过滤当前参与者的DEVICE记录，列表分页按现有Repository处理。

  2. 打开邀请

    按shareId读取当前记录及状态，只有当前接收人的有效待确认邀请才可接受/拒绝。

  3. 提交与核对

    禁用重复点击，命令成功后回查状态，再更新列表及可访问的共享设备；不提前提示处理成功。

  4. 查看共享设备

    已接受邀请按当前scopes进入共享详情；查看设备不创建自有绑定，也不开放所有者档案。

3状态与数字怎么理解

字段 / 区域来源 / 内容处理规则
邀请身份shareId / resourceType / inviterUserId / recipientUserId仅DEVICE，当前参与者与方向匹配；无名称按合法回退，不用合成人物补服务端缺字段。
邀请状态PENDING / ACCEPTED / REJECTED / REVOKED / EXPIRED按服务端记录和有效期判断可执行动作，不用“已读”代替接受。
未读与处置当前没有正式全局未读/已读/处置闭环未知数字不能补0；接受邀请不把设备告警标成已处理。
通知权限Android POST_NOTIFICATIONS / 系统通知开关仅说明手机是否允许通知，不证明FCM/HMS注册、后台到达或点击路由已闭环。

4失败与身份变化怎么处理

  • 结果未确认

    命令超时、取消或回查状态不符先重读，不自动重放接受/拒绝。

  • 撤销或过期

    重新读取后以最新记录决定动作；已失权设备停止读取并清理受限数据。

  • 账号/环境变化

    取消旧列表和详情任务，按新上下文重新读取，旧回包不得覆盖新会话。

  • 通知设置返回

    从系统通知设置回到App时重读本机开关状态；不据此更新服务端消息状态。

5已接入与待验证范围

  • 已有证据

    10-13/19设备分享邀请及双账号链路保留原范围；10-28权限和撤销失权记录见分享专题。本轮只审阅说明，不新建邀请。

  • 尚未闭环

    FCM/HMS SDK注册、Token生命周期、真实后台到达、通知点击及告警去重/已读/处置仍待实施或验证。旧Service/UseCase声明不等于主入口已调用。

  • Mock与原型

    Mock消息与静态原型可展示合成告警；不能把它们算作Prod消息历史或后台推送验收。

公共约定：需登录的业务请求使用 Bearer Token，后台公共层携带 lang 与地区格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。OAuth、账号、AI 客服和图片客户端按各自规则处理。
