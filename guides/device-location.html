地图与立即定位技术说明

地图显示设备最后一次有效上报；立即定位只发指令，新的位置仍从 realtime 获取。

首页聚合自有设备点，详情显示单台设备。当前不把最后位置当作持续实时追踪。

1用哪些接口

  1. 发现当前使用者GET/app/subjects设备发现流程复用设备列表
  2. 获取关联设备GET/app/subjects/person/{personId}/device-bindingsGET/app/subjects/pet/{petId}/device-bindings按 deviceId 合并后读取
  3. 读取最后位置及时间GET/app/device/{deviceId}/realtime首页和设备地图更新位置的来源
  4. 显示在线状态GET/app/device/{deviceId}/state在线状态与位置时间分别判断
  5. 发送立即定位POST/app/device/{deviceId}/functionquery：functionId=singleLocating；JSON body：{}

立即定位入口在云设备详情地图中；首页不自动向全部设备发送指令。

2位置和指令怎么组合

  1. 发现设备

    复用对象 → 绑定 → deviceId 的链路，确认单台详情的设备关系。

  2. 判断位置

    校验 latestLocation 坐标、定位状态及同次上报时间；未取得有效位置时显示空态。

  3. 绘制地图

    原始坐标按当前地图服务转换一次，标记、相机和覆盖物采用一致坐标系。

  4. 立即定位

    确认自有关系，POST 一次；受理后提示已发起请求，继续通过实时数据读取设备实际回传。

3位置字段怎么用

字段 / 区域来源 / 内容处理规则
坐标latestLocation.lat / lng必须是有限 JSON 数值，纬度 −90～90、经度 −180～180；数值字符串不接受，不使用演示点补位。
定位状态latestLocation.locStatus、generalData.isGPSlocStatus 不能为 x（不区分大小写），且 isGPS 必须为 true；不能把非 GPS 自动标成 WiFi 或 LBS。
上报时间latestLocation.dateTime 与 generalData.dateTime两者必须是有效且相同的毫秒时间；当前接受 12–13 位数值或数字字符串，范围为 2000～2100 年。
坐标系统latestLocation.coordinateSystem缺字段才默认 WGS84；明确 null 或未知值不绘点。接受 WGS84 / GCJ02（含连字符形式），按地图服务转换一次；默认仍待后端确认。
指令响应code=0、ok≠false、data 为非空字符串仅确认服务端受理；不代表设备已执行、定位成功或位置已更新。

4刷新和失败怎么处理

  • 刷新位置

    前台轮询已有设备，离页 / 后台停止；正常数据更新保持用户拖动或缩放后的视野。

  • 主动回位

    只有明确的回到设备操作才主动调整视野；切换地图服务时重新按服务坐标规则绘制。

  • 指令拒绝

    服务端明确离线或拒绝时给出对应反馈，不能用成功 Toast 掩盖失败。

  • 指令结果不明

    超时、断网、响应不完整时不自动重发；按钮并发调用不排队，避免后续补发重复指令。

  • 旧位置

    允许展示有明确时间的最后上报，不推算移动；鉴权拒绝和关系失效后不继续沿用受限数据。

5哪些内容还要补

  • 后端待确认

    正式坐标系、时间类型及单位、立即定位的设备执行结果与超时规则。

  • 尚未验证完整

    真实硬件持续移动、轨迹、围栏和 Google 卫星图；原型轨迹与围栏不能作为已接入依据。

公共约定：业务请求带 Bearer Token 与 IANA 格式的 X-TimeZone；ID 保持无损，写入结果不明时先回查。认证、图片等专用客户端按各自规则处理。
